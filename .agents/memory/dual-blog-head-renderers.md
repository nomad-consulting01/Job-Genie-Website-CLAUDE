# Dual blog head renderers must stay in sync

Blog post `<head>` markup (meta + JSON-LD) is generated by **two independent renderers**:

1. **Static prerender path** — `entry-server.tsx: getBlogPostHeadHtml` (runs at build time, serves most published posts via `dist/public/blog/<slug>/index.html`; production static handler serves these FIRST)
2. **Dynamic SSR path** — `blog-html.ts` in the api-server (serves only posts published after the last build)

**Why:** An AEO fix (JSON-LD `image`, `dateModified`, full `acceptedAnswer.text`) was applied only to the dynamic path; a code review caught that the majority of traffic (prerendered posts) never got it.

**How to apply:** Any change to blog SEO/meta/JSON-LD must be made in BOTH files, then the frontend rebuilt (`PORT=19806 BASE_PATH=/ pnpm --filter @workspace/job-genie run build`). Also: JSON-LD embedding DB content must escape `<` (`.replace(/</g, "\\u003c")`) — both files have a `jsonLd`/`jsonLdStr` helper for this.

Related gotcha: SSR route list in `entry-server.tsx: render()` is separate from client `App.tsx` routes — a route missing there prerenders the wrong page body (happened with `/free-autopsy`, which fell through to the catch-all `LandingPage` and the generic `noindex` head fallback).

Blog body formatting also has separate prerendered, dynamic fallback, and client-rendered paths. Updating only the client article does not fix the initial HTML visitors may see.

**Why:** A Facebook-linked article exposed missing heading-to-paragraph spacing in initial HTML even though the client article had typography classes. Tailwind's reset removes the browser's default margins.

**How to apply:** Check body-formatting changes against all three rendering paths, not just the interactive page. Keep scoped article spacing in both the built stylesheet and standalone dynamic HTML.
