---
name: Stale static build on redeploy
description: Editing source assets (e.g. favicon, public/ files) isn't enough — the static production build dir must be rebuilt or a republish ships the old files
---

For artifacts with `serve = "static"` (e.g. job-genie, `publicDir = "artifacts/<name>/dist/public"`), editing files in `public/` or `index.html` does NOT automatically update `dist/public/` — that directory is a build artifact checked into the workspace and only regenerated by running the build command.

**Why:** if you edit source assets and tell the user to republish without rebuilding first, the deploy step may reuse/produce a build from stale inputs, or the user's republish flow may not always trigger a fresh full rebuild — shipping old files (e.g. old favicon.svg) even though source is correct.

**How to apply:** after changing anything under an artifact's `public/` dir or other build inputs, manually run the artifact's build command locally (see `vite-build-env.md` for job-genie's required env vars) and verify `dist/public` reflects the change (`grep`/`ls` for the expected file) BEFORE telling the user to republish. Don't just trust source-level edits.

Also: browser favicon caching is extremely aggressive and separate from normal HTTP cache — even after a correct deploy, an already-open tab may keep showing the old favicon. Verify server-side correctness with `curl -I` on the live URL, and have the user check in an incognito window rather than assuming the fix failed.
